# 0.33.2 — облако через публичный SDK

По решению владельца синхронизация выполняется при запуске и примерно раз в пять минут. Локальный браузерный журнал записывается сразу.

## Изменения

- Удалён вызов внутреннего транспорта SDK. Облако использует документированные `ysdk.getPlayer()`, `player.getUniqueID()`, `player.isAuthorized()`, `player.getData()` и `player.setData(data, true)`.
- Один объект `Player` используется для одного цикла чтения, объединения и записи. Повторно полученный объект с уже прочитанным кэшем не разрешает новую запись поверх облака.
- После чтения серверного снимка объединение подтверждается существующим контроллером Unity. Запись выполняется в том же коротком цикле, после сохранения нормализованного состояния игры. Если подтверждение задержалось более 20 секунд, запись откладывается до следующего свежего чтения.
- Окно аккаунта объясняет пятиминутный интервал. Кнопка ручной записи отключена во время ожидания нового цикла; игра продолжает работать.
- Схема прогресса v16, облачный конверт v3 и журнал вкладов устройств сохранены. Объединение складов, квитанции выплат, оплаченные кирки и миграции используют прежнюю логику.
- Версия Unity — 2022.3.47f1. Проверка настоящего iPhone/Safari пропущена по решению владельца; настройки заявленных платформ в консоли не меняются.

Публичные методы и ограничения: [документация Яндекс Игр](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player). Пятиминутный кэш установлен проверкой текущей реализации SDK; документация не обещает фиксированное время жизни объекта. Если SDK продолжит возвращать использованный объект дольше, запись подождёт, а локальный прогресс останется сохранённым.

## Проверка

Тесты SDK и облака используют объект `Player` с кэшем первого чтения и сроком жизни пять минут. Проверяются запуск, граница интервала, запрет записи через старый объект, задержанное подтверждение, два устройства, потеря подтверждения и однократные выплаты.

Браузерный прогон использует настоящую WebGL-сборку, два изолированных профиля, контролируемое облако и виртуальные часы Playwright для перехода пятиминутных границ. Это не проверка настоящего серверного кэша или аккаунта владельца.

Результаты сборок и прогонов записываются в [Verification.md](Verification.md), состояние загруженного черновика — в [YandexDraft.md](YandexDraft.md).

## Ограничения

ММР и монеты двух одновременно работающих устройств могут различаться до следующего объединения; отправка результата в рейтинг имеет отдельный интервал. Мгновенная синхронизация не обещается.

При закрытии игры новый прогресс остаётся в локальном журнале. Если пятиминутный цикл ещё не наступил, другой компьютер получит его после следующей успешной синхронизации этого устройства. Сервер SDK не предоставляет атомарное сравнение и запись: после одновременной записи двух устройств общий журнал восстанавливается при следующем опросе из сохранённых локальных вкладов.

У старых расходящихся сохранений нет полной истории операций: их первый импорт по прежнему решению владельца складывается однократно, неизвестное историческое пересечение восстановить нельзя.
